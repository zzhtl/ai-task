# 0010. 审批、预算与漂移：让定时 AI 任务能进生产

## 状态

已接受（2026-09-09）。

## 背景

前面九个 ADR 解决的是"怎么把 AI 执行跑起来、跑对、跑在别的机器上"。
这一条解决的是剩下那个问题：**怎么敢让它每天自己跑。**

三件事分别对应三种失控：做了不该做的（审批）、花了不该花的（预算）、
悄悄变成了另一个东西（漂移）。

## 审批

### 超时的默认动作是拒绝

`ApprovalTimeout::Deny` 是默认值，也是唯一被实现的默认路径。

超时放行会把审批门变成一个"延迟 15 分钟的空操作"——而配审批门的人，
恰恰是不想让它自动通过的人。

### 等待方式是轮询数据库

决策来自另一个 HTTP 请求，可能落在**另一个副本**上；进程内的 channel
收不到。数据库是唯一的真相。2 秒一次单行主键查询，默认 15 分钟窗口最多
450 次——相对于"人正坐在那里等"，这点开销不值得用 `LISTEN/NOTIFY` 换。

### `ask` 是有界长轮询，不是一个长请求

策略判决命中 `ask` 时，`/internal/policy/decide` **建好审批就返回**，
带上 `pending_approval_id`；hook 再去轮询 `/internal/policy/await`，
每次最多等 10 秒，自己持有整体截止时间。

不让 hook 挂在一个十分钟的请求上，是因为它的超时必须覆盖最坏情况。
一旦把 hook 的 `TIMEOUT` 从 20 秒放大到审批窗口那么长，服务端卡住时
每次工具调用都要挂十分钟才失败，而不是二十秒内快速关门。
**失败模式比等待时长重要。**

而 `/internal/remote/call` 跑在服务端进程里，就地 `await` 不占任何
HTTP 连接，所以它走 `AskMode::Wait`。同一段判决逻辑，两种等待方式。

### 并发决策：谁先到算谁的，但后到的必须知道

`UPDATE ... WHERE decided_at IS NULL` 让两次并发决策只有一次能写进去。
接口返回 `was_first`，后到的那个人看得到实际生效的是什么——
否则点了"拒绝"的人会以为自己拦住了。

### 卡片渲染结构化意图，不是自然语言

要让人在几秒内判断"这该不该做"，卡片上必须是具体的：哪台机器、
跑什么命令、改哪个文件。一段"我将执行一些维护操作"只会让审批
退化成无脑点通过。

剩余时间由**服务端**算好给（`expires_in_s`）。前端自己拿 `expires_at`
减本地时钟的话，客户端时钟偏几分钟就会把还能点的卡片显示成已过期。

## 预算

### run 级闸门在批与批之间生效

节点级的 `--max-budget-usd` 管得住单个节点，管不住"十个便宜节点加起来超了"。
`DagSpec::budget_usd` 是 run 级的：每批节点跑完后检查累计成本，超了就
不再启动新节点。

已经花掉的钱拦不住（那笔钱真的花了），所以终态里的 `cost` 是真实值，
不是被截断的。run 落 `RunStatus::BudgetExceeded`，与 `Failed` 分开——
"钱不够"和"任务写错了"要动的是不同的旋钮。

实测：$0.03 上限、四个串行 AI 节点，第一个 $0.026、第二个 $0.006，
累计 $0.032 超限，n3/n4 没有启动。

跳过的节点报的是"预算已用尽，未启动"，不是"上游失败"——
审计日志里一句说不通的话，比没有这句话更费时间。

## 漂移

### 指纹描述输入条件，摘要描述输出

`fingerprint` = 任务版本的 prompt/模型/effort/tools + 规则哈希 + skills。
刻意**排除** `host`、`limits`、`retry`、`timeout`：换台机器跑、调个重试次数，
不该算作"行为条件变了"，否则把任务挪一台机器就丢掉了所有历史基线。

`output_digest` = 输出的**稳定子集**的哈希。

### 只有"输入没变、输出变了"才告警

输入条件变了而输出跟着变，那是**改动生效了**，不是漂移。
`Drift::is_alarming()` 就是这个与条件。差异照样列出来，只是不报警。

### 稳定子集：靠标点分辨标识与叙述

数字、布尔留下；字符串按"是标识还是叙述"判断。

**不能只按长度判。** 一句中文叙述常常只有十几个字符，比一个域名还短
——第一版用 32 字符阈值，测试里 `"发现了三个问题，建议尽快处理相关配置项。"`
被当成了枚举值。真正的分界是**标点和空格**：它们只出现在句子里。
`healthy`、`web-1.prod.internal`、`/var/log/app.log`、`ERR_502` 留下；
带 `。，、；！？` 或空格的一律当叙述剔除。

这是没有 schema 时的兜底。**想可靠地盯住某个结论，就用 `output_schema`
把它声明成数字或枚举**——那才是契约，上面这套只能做到"多数时候对"。

### 影子执行必须真的没有副作用

`dry_run` 原本只在**策略层**实现，而策略层只看得见模型发起的工具调用。
`shell` 和 `approval` 由引擎直接执行，绕开了那一层——实测撞到过：
一个 `dry_run` 的 run 真的在目标机上 `touch` 出了文件。

修法是一个穷举匹配的 `suppressed_by_dry_run(dry_run, config)`：新增节点类型时
编译器会逼着在这里做出选择。AI 节点照常跑（影子执行要的就是"看看模型这次
会得出什么结论"），shell 与 approval 只记录意图。

同一轮还发现 `StructuredOutput` 被 `is_write_tool` 判成了写类工具，于是
`dry_run` 的 run **永远产不出结构化输出**——而影子执行的全部意义就是拿输出
比基线。模型反复重试那个工具，烧掉 $0.058 后以"输出不符合契约"失败。

## RBAC

### 按方法判，不按路径枚举

读是 viewer，写是 operator，主机/策略/审计是 admin。

按路径逐条配的话，新加一个接口忘了配就等于**默认放行**——这类遗漏没有任何
症状，直到有人用它做了不该做的事。按方法判之后，明天加的接口今天就有正确的
默认值。

角色用序关系（`Role: Ord`）而不是逐个列举，新增中间档位时所有检查点自动跟着对。

### 默认不开认证，但对外暴露时强制开

`AI_TASK_REQUIRE_AUTH` 默认 `false`：默认只监听回环，单人自托管时逼着先建
账号是纯粹的摩擦。

但 `--listen` 一旦离开回环而没开认证，**进程拒绝启动**。这个服务能 SSH 到
任意机器执行命令，"启动了但不安全"要等出事才被发现。

### 登录接口不能变成用户名枚举器

用户不存在时也跑一次 argon2 校验（拿一个运行时算出来的真哈希去比）。
占位哈希写成字面量的话，格式一旦不合法 `verify` 会立刻返回 false 而
**不做任何计算**——"用户不存在"又变回一条快路径。这个失败是静默的，
所以有一条测试在断言两条路径的耗时在同一量级。

会话 token 走 HttpOnly cookie 而不是 `localStorage`：后者对页面上的任意脚本
可读，一次 XSS 就等于长期会话被拿走。库里只存 token 的 SHA-256。

### 改角色立刻生效，停用才需要吊销会话

`principal_for` 每次请求都重算角色，所以降级不用等重新登录。

停用则会连带删掉该用户所有会话。`principal_for` 本来就会挡住 disabled 的用户，
删会话是第二道：万一哪天那个条件被改掉了，已经发出去的 token 也不该还能用。
另外提供了单独的"踢下线"——改口令**不会**让已发出的 token 失效，口令泄漏时
需要一个直接的手段。

### 最后一个管理员摘不掉

摘掉之后加人、改角色、看审计全都做不了，只能去改库救。这个操作没有撤销键。

判定条件是"**目标当前就是管理员**且启用中的管理员只剩一个"。第一版漏了前半句，
结果把一个 viewer 升成 operator 也被拦成了"最后一个管理员"——动一个非管理员
不可能减少管理员数量。

## 漂移主动告警

run 落终态之后，和上一个同指纹的成功 run 比一次；**真有漂移才**写一条
`DriftDetected` 事件并打 WARN 日志。

主动发而不是等人来问：一个每天自己跑的任务悄悄变了样，如果只有点进详情页
才看得到，那等于没有检测。

比较用的是**本次刚算出来的指纹**，不是 `run.fingerprint`——那条记录是执行
开始前读的，那时指纹列还是空的。第一版用了后者，结果比较被静默跳过、
一条事件也不发。
