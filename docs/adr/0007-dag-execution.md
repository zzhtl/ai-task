# 0007. DAG 执行：map 是节点内扇出，就绪判定看入边

## 状态

已接受（2026-09-08）。

## 决策

DAG 编排在 `ai_task_runtime::dag` 里，纯逻辑部分（输入求值、条件求值、
输出契约校验）在 `ai_task_core::eval`。

### `map` 是节点内部的扇出，不是图重写

展开出来的实例在事件日志里各占一行（靠 `instance` 区分），但**图本身不变**：
map 节点的输出就是各实例结果的数组，下游像读普通节点一样读它。

替代方案是运行时往图里插节点。那会让拓扑序、就绪判定、取消传播全部从静态问题
变成动态问题——每加一个实例都要重算一遍，而且事件日志里的图和 spec 里的图对不上，
回放时无法重建。不值得。

代价：一个 map 节点内部不能再有分支（模板是单个节点）。真需要子图时再说。

### 就绪判定看入边，不看拓扑序

一个节点只有在它**所有**入边的上游都已终态之后才可判定；至少一条入边放行就执行，
全部否决就**跳过并发事件**。

最后半句是踩出来的：第一版只在内存里标了 `Skipped` 却没发事件，结果被条件边
跳过的节点在界面上永远停在 pending，`RunState::replay` 也不会把它标成终态。
三条测试同时挂在这上面。

### 失败边不在取消和跳过时触发

`on_failure` 只对 `Failed` 生效。把 `Cancelled`/`Skipped` 也算进去的话，
用户一按取消就会触发一整排「失败处理」分支。

## 几个刻意的取舍

**单实例上游不套数组。** 上游被 map 展开过时，下游读到的是全部实例拼成的数组；
只有一个实例时保持原样。否则同一份 spec 在扇出 1 个和 3 个时，下游要写两种取值方式。

**JSONPath 匹配到一个就给原值，匹配到多个才给数组。** `$.count` 应当得到 `4`
而不是 `[4]`。匹配到零个是**错误**，不是 `null`——静默给空值会让下游拿着它继续跑，
错误要到很后面才暴露。

**失败的 map 分支占位而不是被剔除。** 输出数组里放
`{"__failed": true, "error": "..."}`，下游按下标还能对回输入。剔除的话下标就错位了。

**map 的 `max_items` 有默认值且必须生效。** `over` 来自 AI 输出，一个失控的数组
能瞬间放大成几千个节点。截断时如实报出「上游给了 N 项，只处理前 M 项」。

**重试退避封顶 30 秒。** 指数退避不封顶的话，第 10 次重试要等几个小时。

**校验失败的错误原样回喂给模型。** 不是一句「格式错误」，而是「哪个字段、错在哪」。
回喂内容拼在提示词**最后**——模型对靠近结尾的指令更敏感，而这正是本轮最要紧的信息。

## 测试策略

节点执行抽成了 `NodeRunner` trait，编排逻辑用一个按脚本回答的假执行器测试：
条件边、重试、map 展开、取消这些逻辑的 bug 不该靠烧 API 额度去发现，也不该
需要起数据库。事件写入同样抽成了 `EventWriter`，测试里换成一个只记录的实现，
顺带能直接断言事件序列。

真实链路由一次端到端跑覆盖：4 节点 DAG（探测 → 扇出 3 路诊断 → 断言 → 汇总），
$0.124，3 个 map 实例并发启动，取消后 0.25 秒内全部收敛且无残留子进程。

## 前端

`@xyflow/svelte` 1.6.6（要求 svelte ^5.25，实测与 5.57 兼容）。布局自己算：
按最长路径分层、层内平均分行，三十行，不引 dagre。

用最长路径而不是最短：一个节点应当排在**所有**上游的右边，否则菱形拓扑里的长边
会从右往左画回去。

同一个画布组件既用在任务页（编排视图），也用在 run 页（叠加实时状态）——
看一个正在跑的 run 时不用在「图」和「事件流」之间来回对照。

YAML 是编辑时的真相来源，画布是它的实时视图；解析失败时保留上一次能画出来的
spec，免得敲到一半就白屏。**反方向（在画布上拖出节点）没做**，那是结构化编辑，
另一个量级的工作量。
