# 0002. HTTP 契约

## 状态

已接受（2026-09-08）。

## 决策

### 错误信封

```json
{ "code": "not_found", "message": "…", "request_id": "0199…", "details": [] }
```

`code` 是契约（新增兼容、改变触发条件是破坏性变更），`message` 不是（文案随时
可改，客户端不得拿它做分支）。`details` 装字段级校验失败，**一次返回全部**，
不是只报第一个。`request_id` 同时出现在响应头 `x-request-id` 和该请求的所有
日志里。

### 状态码

| 情形 | 状态码 |
|---|---|
| 报文解析不了 | 400 |
| 报文合法但语义非法 | **422**（全项目只用 422，不与 400 混用） |
| 未认证 / 已认证但无权 | 401 / 403 |
| **跨租户资源** | **404**（返回 403 等于确认了它的存在） |
| 版本冲突、重复、非法状态迁移 | 409 |
| 限流 | 429 + `Retry-After` |
| 依赖不可用 | **503 + `Retry-After`**（不是 500） |
| 意外 bug | 500，细节只进日志，响应体只留 `request_id` |

### 表示约定

- 时间 RFC 3339 带 offset；ID 是不透明字符串；**金额是十进制字符串**
  （JS 的 `Number` 会丢精度，所以连数字形式的输入都拒绝）
- 枚举是字符串，**客户端必须容忍未知值**；前端对未识别的 `RunEvent.kind`
  应降级显示原始 JSON，不能崩溃或静默丢弃
- 字段命名统一 snake_case
- 未声明的查询参数**拒绝**而不是忽略——静默忽略会把一个拼写错误变成「返回全部」

### 其它

- **分页一律游标**（`(created_at, id)` 唯一且稳定），`limit` 服务端封顶 200，
  默认不返回总数
- **幂等**：创建/触发类 POST 走 `Idempotency-Key` 头；响应与副作用必须写在
  **同一个事务**里，重放返回存下来的响应；同 key 不同 body 返回 409；过期
  窗口 ≥ 24h
- **并发**：更新走 `ETag` / `If-Match`，冲突 409
- **触发 run 返回 202** + `Location`，不是 201
- **不加 CORS**：前后端由同一个二进制 serve，开发期走 Vite 代理。这个服务能
  SSH 到任意机器执行命令，放开跨域是不必要的攻击面
- **默认监听 127.0.0.1**，对外暴露必须是显式选择

## 取舍

**没用 RFC 9457。** 规范的字段名是 `type`/`title`/`detail`/`instance`，没有
客户端消费那几个额外成员，而本仓库其它服务（`transfer-app/src/error.rs`）
已经用 `{code, message}`。跨服务一致比贴合规范更有价值。代价：将来要对接
消费 problem+json 的第三方网关时得加一层转换。

**422 而不是 400。** 两者都常见，重要的是**不混用**。选 422 是因为它把「我读
不懂你的报文」和「我读懂了但你说的不对」区分开，后者才配得上 `details`。

**跨租户返回 404 而不是 403。** 会让「资源不存在」和「不是你的」在客户端看来
一样，调试时略麻烦；但 403 等于向探测者确认了 ID 的存在。

**`AppError` 只保留当前真正会被构造的变体。** 上表是完整策略，但代码里没有
handler 用的变体不提前写——用到哪个，连同它的测试一起加回来。
